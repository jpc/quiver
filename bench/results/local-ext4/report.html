Recommended settings for this filesystem

  • --shards 1 is fine here — splitting output across 4 sinks changes throughput by only 1.1×.
  • --frame-mb 2 — knee of the chunk-size curve.
  • -j 8 worker threads per node for write-bound work.
  • Buffered writes do not rescue single-inode contention (0.47 vs 0.68 GB/s O_DIRECT).
  • Spread creates across directories — 5.8× from 1 → 256 dirs (26,283 → 151,888 files/s). Directory locking, not bandwidth.
  • Scan: d_type is 3.6× faster than lstat — enumerate-only paths (rm, delete) should never stat.
  • Fastest hash here is xxh64 two-seed (128b) (3.89 GB/s), but chunk IDENTITY must be cryptographic — use BLAKE3 (2.12 GB/s). A forgeable collision is silent dedup corruption.
